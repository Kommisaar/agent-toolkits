# Balanced 均衡迭代

## 适用场景

用于日常迭代，在系统质量与仓库已有路线图之间保持平衡。可以推进有明确依据的小功能
切片，但不能据此虚构产品需求或绕过中高风险确认。

## 默认运行策略

- 未指定任务预算时，以“一批、最多合并 3 个任务”为默认预算。
- 默认并发 2；只有第三个任务与在飞任务不存在文件、契约和共享配置耦合时才提升到 3。
- 只自动执行 `low` 风险任务；`medium` 风险先说明收益、影响面和回滚方式并请求确认。
- 质量任务与功能任务同时存在时，至少保留一个并发槽位给正确性、测试或门禁问题。
- 完整基线门禁和合并前完整门禁不可降低；功能切片额外验证用户行为和兼容性。

## 可自动选择

- `conservative` 策略允许的全部任务；
- 仓库路线图、设计文档或明确 TODO 中可独立验收的小功能切片；
- 不改变公共契约的内部能力补齐；
- 有测试或基准支撑的局部体验、可访问性和性能改进；
- 与当前目标直接相关且可回滚的工程效率优化。

## 需要确认

- 任何 `medium` 或 `high` 风险任务；
- 用户可见行为、默认值或兼容性发生变化；
- 新增依赖或现有依赖的非补丁升级；
- 公共 API、schema、序列化、权限和数据生命周期变化；
- 多模块重构、生成链路变化或无法完整运行门禁。

## 默认禁止

- 没有用户、路线图、设计文档或现有行为依据的新功能；
- 数据迁移、生产操作、部署和远端资源修改；
- 为提高并发而拆出无法独立验收的任务；
- 用跳过测试、降低规则或扩大忽略范围换取门禁通过。

## 排序偏好

1. 阻断当前目标的正确性、安全和门禁问题；
2. 能降低后续功能风险的测试与契约补强；
3. 证据清楚、范围小的路线图功能切片；
4. 性能、可访问性和工程效率；
5. 与当前目标无直接关系的技术债。

## 完成标准

- 每个功能变化均能追溯到用户授权或仓库证据；
- 中风险及以上决策有明确确认记录；
- 任务级测试、完整门禁和 reviewer 结论可核对；
- 没有未说明的公共契约、依赖、锁文件或生成物变化；
- 最终批次同时说明业务收益与质量影响。
