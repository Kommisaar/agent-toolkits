# ui-design：前端设计品味

让产出的界面摆脱模板感：每个视觉决定都有理由，能回答「为什么是这样」。本 Skill 只约束视觉与结构决策；动效的系统规范（时长、缓动、编排）由后续动效 Skill 提供，这里只约束与视觉不可分的入场方式。

## 心态

以被雇佣的设计负责人自居，而不是执行模板的排版员：拿到需求先形成判断与主张，敢于做有依据的大胆决定。通用、安全、放哪都成立的方案视为未完成——设计的区分度来自产品所在领域与其自有语言（儿童玩具与金融仪表盘不该长得一样），不来自流行的配色与圆角。

## 第一步：先理解，再决定

动手前先回答三问，答案决定后续一切选择：

1. 这是什么产品，处于什么行业与语境？行业自有视觉词汇（衬线与留白之于出版、等宽与低饱和之于开发者工具）是区分度的第一来源。
2. 给谁看，在什么场景下看？受众的专业度、设备与注意力状态决定信息密度、字号与克制度。
3. 这个页面或组件要达成什么？写出唯一的首要目标，次要目标靠让位实现。

需求模糊、缺少品牌约束时，不要默认走「安全通用」路线：先提出 3 个方向差异明显的视觉主张（如克制的编辑风、高对比的产品风、轻量的工具风），每个附一句理由与适用场景，请用户选定后再深入；用户给出明确方向后照做到底，不再反复摇摆。

## 第二步：先立 token，再写代码

写任何组件代码之前，先产出一页设计 token 并自查，模板与排版细则见[设计 token 与排版规则](references/design-tokens.md)。要点：

- 颜色 4–6 个命名色起步，命名表达用途而非外观（`bg-surface`、`accent`），先中性色阶后唯一强调色；
- 至多两款字体（两款时需明显区分）、字号 5–6 档，层级靠字号、字重与留白表达，不靠加颜色和全大写；
- 间距用统一基数（4 或 8），圆角与阴影各至多两档；
- 关键布局先用 ASCII 线框画出区块与主次，确认视线落点后再翻译成代码。

token 一旦确定，代码里不再出现散落的魔法值；改风格改 token，不改组件。

## 第三步：自查「AI 味」

对照[反模式清单](references/anti-patterns.md)逐条检查配色、布局、排版、装饰与文案。判定原则：一个视觉手法若换成任何产品都成立，它就没有承载信息。清单是默认禁用而非绝对禁令——用户或品牌系统明确要求时照做，但把免费的创意额度花到别处，不要又滑回清单内套路的变体。

## 结构与层级

- 装饰必须承载信息：分隔线表达分组、编号只用于真实顺序、边框与底色表达从属关系；纯装饰元素逐个质询能否删除。
- boldness 花在一处：整个页面保留一个记忆点（一个大字标题、一个强色块、一处特异布局），其余全部安静；处处强调等于没有强调。
- 用留白与对齐组织信息，而不是用框：相邻即相关，组间距大于组内距；先试无框方案，框是最后手段。
- 视觉重量有唯一序：首屏视线应有唯一落点，动线从主到次可预测。

## 质量底线（不可妥协）

以下不是风格偏好，是完成标准，任何「下一步再补」都视为未完成：

- 移动端可用：375px 宽度下布局不破、文字不溢出；
- 键盘可达：可交互元素有可见 focus 态，Tab 顺序符合视觉顺序；
- 对比度达标：正文 ≥ 4.5:1，大字 ≥ 3:1；
- 尊重 `prefers-reduced-motion`：入场与装饰动效必须可降级；
- 暗色模式如适用，token 双套定义，不做简单反色。

## 文案即设计

界面文字是设计内容而非填充物：按钮用动词短句（「保存更改」优于「提交」）；错误信息指向下一步行动而不是道歉（「文件超过 10MB，压缩后重试」优于「抱歉，出错了」），空状态是行动邀请而非空白装饰；同一概念全站用同一个词，同一动作全程同名（按钮叫「发布」，成功的提示就叫「已发布」）；不写用户不会读的装饰性说明文字。

## 完成前自评

1. 按 token 清单核对代码：无魔法值、无清单外的颜色与字号；
2. 对照反模式清单过一遍，命中的条目要么替换、要么写明保留理由；
3. 截图（宽屏与 375px 至少各一张）自问：视线落点在哪？记忆点是哪个？哪个元素删掉也不损失信息？——答不上来就回炉。
